# 0003. 右クリックメニューから外部APIへ送るサンプルのコントラクトを決める

## 背景

issue #4「右クリックのコンテキストメニューを追加し、外部APIに向けてリクエストを送る機能のサンプルを
作成する」は、issue本文が空（目的・現状・期待する動作・受け入れ条件のいずれも未記載）の状態で着手
することになった。Python API本体（[README.md](../../README.md)が想定するFastAPI）は別リポジトリの
スコープであり、本リポジトリ側だけでは正式なAPI契約を決定できない。そのため、着手前にユーザーへ
以下3点を確認し、暫定のコントラクトとして本DDRに記録する（詳細仕様は
[docs/spec/右クリックで外部APIへリクエストを送信する.md](../spec/右クリックで外部APIへリクエストを送信する.md)
参照）。

## 決定

1. **「外部API」= README.md記載のPython API(FastAPI)想定とする。** Python API自体の実装・起動連携は
   別リポジトリ／別issueのスコープとし、本issueでは拡張側から見た通信サンプルのみを扱う。
2. **コンテキストメニューはエディタ（`editor/context`）とエクスプローラー（`explorer/context`）の
   両方に追加する。** ユーザー確認の結果、片方に絞る理由が無かったため両方とした。
3. **リクエスト内容は「右クリックしたファイルのパスをPOST送信する」サンプルとする**
   （`POST {apiBaseUrl}/analyze`, body `{ "path": "<ワークスペース相対パス>" }`）。
   README.md 13節の「ファイルを選択→右クリック→送る」というUXに最も近い、かつ拡張側の実装が
   まだ無い状態から一歩進んだ最小サンプルとして採用した。
4. **API URLは固定値ではなくVS Code設定（`vscode-gws-extension.apiBaseUrl`、既定値
   `http://localhost:8000`）で持たせる。** README.mdは将来的に動的ポート（拡張activate時にPython API
   を起動し、`API_READY:<port>`のような形でポート番号を通知する）を想定しているが、その起動連携自体は
   別issueのスコープのため、今回は「ユーザーが設定で指定できる」形に留めた。

## 却下した案

- **`GET /health` へ疎通確認のみ行う案**: 実装は最小限で済むが、右クリックしたファイルの情報を
  一切使わないため、「コンテキストメニューから送る」という体裁のサンプルとしての説明力が弱いと
  判断し、選択ファイルパスを送信する案を採用した。
- **API URLをコード上の定数として固定する案**: 実装は簡潔になるが、Python API起動時のポート番号は
  ユーザー環境やPython API側の実装によって変わりうるため、設定で変更可能にしておく方が将来の
  動的ポート対応（別issue）への移行コストが小さいと判断した。
